Support

Common questions, and what to try when something is not working.

Frequently asked

Are my files really not uploaded?

Correct. Tools read your file with the browser's File API and process it in memory. There is no upload endpoint to send it to.

You can confirm it: open developer tools, go to the Network tab, and run a tool. The only requests are for the page's own scripts.

How large a file can I process?

There is no server limit, so the ceiling is your device's memory. On a modern laptop: images up to roughly 50 megapixels, PDFs of a few hundred pages, and audio or video up to around 500 MB are comfortable. Phones and older machines handle noticeably less.

If a tab crashes or the tool stalls, the file was too large for the available memory. Try a smaller file, or lower the output resolution.

Does it work offline?

Mostly. The site installs a service worker, so the pages and scripts are cached after your first visit.

Tools that pull in a library on first use — PDF editing, OCR, QR codes, MP3 encoding, GIF creation — need a connection the first time you run them. After that the browser caches the library too.

Which browsers are supported?

Current Chrome, Edge, Firefox and Safari, on desktop and mobile. A few tools depend on newer capabilities: AVIF export needs a recent Chrome or Firefox, and the tool will tell you if your browser cannot save that format rather than silently producing a PNG.

A tool gave an error. What now?

Reload the page. This clears any half-loaded library.

Check the file. Password-protected PDFs must be unlocked first. Some MKV and AVI files use codecs browsers cannot decode; convert to MP4 or WebM first.

Try a smaller file to rule out a memory limit.

Check for a blocker. Some tools fetch a library from jsDelivr; a strict content blocker or firewall can prevent that.

Why did compressing my PDF make it bigger?

PDF compression rasterises each page into an image. For a text-heavy PDF that is already efficiently encoded, images are larger than the text they replace. The tool detects this and tells you to keep your original.

Compression pays off on scanned documents and image-heavy PDFs, which is where the large files usually are.

I lost the passphrase for an encrypted file.

The file cannot be recovered. Encryption uses AES-256-GCM with a key derived from your passphrase; no key is stored, and no copy of your file exists anywhere else. This is what makes the encryption meaningful, and it also means there is no reset.

Can I self-host it?

Yes. It is a static site with no build step — clone the repository and serve the folder. The AGPL-3.0 licence asks that you make your modified source available to your users.

Reporting a problem

Open an issue on the GitHub repository. It helps to include the tool name, your browser and version, roughly what the file was (type and size), and anything shown in the browser console.

Please do not attach confidential files to a bug report. A small example that reproduces the same problem is more useful and safer for you.
