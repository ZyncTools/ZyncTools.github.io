Run it on your own network

ZyncTools has no backend. Every tool runs in the browser, which means the whole suite is a folder of static files — and a folder of static files can live on your intranet, behind your firewall, with no route to the outside world at all.

The problem this solves

If you handle documents that belong to somebody else — a client contract, a patient record, a tax return, a signed offer letter — you are usually not allowed to upload them to a third-party website to be processed. Not because the website is untrustworthy, but because sending the file is itself the disclosure.

So the work gets done some other way: an expensive desktop licence for everyone who might occasionally need to merge two PDFs, or a shadow-IT habit of using a free site and not mentioning it.

There is no upload step to review. The file is opened by the browser, changed by the browser, and saved by the browser. Nothing is transmitted, because there is nowhere for it to be transmitted to.

What deploying it actually involves

It is a static site. There is no database, no runtime, no container, no scheduled job and nothing to patch on a server.

  • Copy the folder onto any web server, file share or intranet host.
  • Serve it over HTTPS so the browser grants clipboard and file access.
  • That is the deployment.

A handful of tools reach out to a public CDN the first time they are used, to fetch a library for a heavier job like OCR or PDF rendering. Those files can be vendored locally instead, so an air-gapped install never makes a single outbound request. Ask and we will point you at the list.
